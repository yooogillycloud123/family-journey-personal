## Root cause verified against exact R588 APK bytecode
- Extract signed R588 APK `classes7.dex`, class `MoaMomentMemoRecorderActivity`, method `saveNote()`. Existing original onclick is attached to the Save button in `onCreate()`. The handler checks:
  - `MoaMomentCaptureService.prefs()` = SharedPreferences `moa_camera_native_v1`.
  - `getString("m:" + intentMediaId, "")`.
  - On empty result, immediately `status("촬영 기록을 찾지 못했어.")` and **return with no write**. Thus user sees an attempted Save being rejected by an absent camera draft, not evidence that native Save OnClick was removed.
- Original `MoaMomentDirectDiaryStore.start()` in `classes4.dex` requires legitimate `id` plus capture time `at`, note and `memoSaved`. Simply skipping this return would create an orphan record ignored by diary sync.
- Cause of the missing `m:<id>` record on the user device (capture polling race, media access/permissions, or persisted stale intent) **is not uniquely established** without private on-device trace. The patch covers only **real MediaStore media with a recoverable ID**.
