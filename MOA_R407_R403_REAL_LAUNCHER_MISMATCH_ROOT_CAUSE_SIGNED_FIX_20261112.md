- **Direct APK Manifest proof:** exact delivered R403 signed APK original cert and DEX verified; enabled launcher alias `com.juhyeon.familyjourney.MoaIcon_A_modern_bold_pink` has MAIN/LAUNCHER and targets actual **`com.juhyeon.familyjourney.MoaIconHost`**, not `HostActivity`.
- **Exact R403 Java defect:** `MoaR391SessionPersistProvider.valid(Activity)` returns true only for `HOST.equals(a.getClass().getName())`, with `HOST="com.juhyeon.familyjourney.HostActivity"`. Consequently a normal launcher `MoaIconHost` misses `onActivityCreated` Run registration; `onActivityResumed` lacks a Run and never invokes the intended dispose → start → 460ms → hide. The display seen at app launch was the preexisting app splash, not proof that the R403 native mask actually started.

With R403 startup disabled by class mismatch, first tap satisfies `!running`, posts visible, returns `QUEUED_VISIBLE`; the screenshot/video match precisely.
- Real controller `MoaNaverWebProbeController.scheduleExpiry()` has hard `4*60*1000L` expiry and dispose. R407 does **NOT** change this. Even if initial startup works, a later save after expiry could invoke original visible fallback again. Do not claim "always offscreen" or indefinite readiness.
