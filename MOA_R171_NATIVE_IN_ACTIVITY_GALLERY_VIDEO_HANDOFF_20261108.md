## Technical change and limits
1. R171 removes the default HTML5 WebView `content://` playback attempt. Instead `MoaLocalAudio.openInlineVideo(id,x,y,w,h,viewportWidth)` uses the app's authorized `MediaStore.Video.Media` row and **Android `VideoView` (backed by `MediaPlayer`) inside the EXISTING `MoaMomentAudioHostActivity`'s `android.R.id.content`**. The new frame overlays only the current WebView media-stage rectangle using pixel scale from `web.getWidth()/window.innerWidth`; NO second app/Activity/intent in the success path.
2. Starts video muted by default; controls are native play/pause, accurate current/total time label and `SeekBar`, unmute/mute, adjacent photo/video prev/next, touch swipe prev/next, and **user-triggered frame save** via `MediaMetadataRetriever` to `Pictures/MOA-Video-Captures`, leaving video unmodified. On prepared, native overlay fades into the existing poster (150ms). Stops/removes native frame when photo selected, viewer closed, app paused/destroyed.
3. Viewer JS `MoaInlineVideo.mount` now calls only this native same-Activity method, listens for `started/error/next/prev` events, and never automatically launches native external playback as a fallback. If the device cannot open the M4A... [correction: video MP4] media, original poster stays with ▶; **only a deliberate user tap** launches the old native player as fallback (one back stacked window not guaranteed for that emergency path).
4. Both Diary R133 and monthly R141 photo/video viewers gain a **bounded 13-neighbor thumbnail filmstrip**, with native video next/prev callbacks moving to adjacent photos/videos. No all-700 media DOM materialization; original virtualized monthly grid and scroll navigation preserved. Existing day/full viewer buttons and sharing intact.
5. This is *not* Samsung proprietary Gallery app. Native `VideoView` rendering, stage coordinate/insets, MediaStore video permission, actual in-view autoplay and capture, orientation/gesture and hardware Back **NOT independently physical-device verified**. Do not claim equal visuals/behavior until hardware test. A 2nd Activity can still be launched if the **user explicitly invokes** the old fallback, rather than the ordinary path.
