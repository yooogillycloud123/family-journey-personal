## 1. Source-confirmed causes and scoped changes (not invented workarounds)
1. **Black photo sides/video**: exact R567 native `MoaR507InlineGalleryProvider.java` used `ImageView.ScaleType.CENTER_CROP` for full native photo views and original asynchronous blurred ambient full frame for non-fill video. Later revisions removed crop and substituted black standby. R578 restores R567 `CENTER_CROP` on the actual original ImageView and the original video ambient creation/alpha handling. No extra opaque curtain, new video playback engine, or geometry rewrite. Exact user-visible video first-frame flash still REQUIRES Galaxy test.
2. **Red hatched rail–action gap**: R576 `r576TightenMeasuredRail()` measured `nativeLower` entire child group, including video volume/play/seek controls, instead of actual thumbnail filmstrip. Thus shrinking a layout width/height didn't necessarily move filmstrip. R578 measures **actual `railView` rendered bottom → `actionDeck` top** and changes `railView.setTranslationY(desired)` only to approach ~5dp gap, bounded in same host, preserving filmstrip touch object, velocity, rail OverScroller and individual action listeners. This is not a new full-width gray bar.
3. **Quick Record detailed diary exists but photo-form blank**: underlying JS native-save writes original IndexedDB `curated` but photo-form JS may see an initially empty/stale `FamilyJourneyDiary.state.curatedEntries` map. R576 calendar invalidation keyed only sizes (`curatedEntries.size`, etc.) so **same-date newly inserted record with unchanged size was not refreshed**. R578 reads **existing `curated`** record by selected day in readonly IndexedDB transaction on day opening/cold-start and when photo IDs approx or empty, rehydrates only existing in-memory state (no DB writes, media mutations, or account changes). Calendar refresh key now includes content/updatedAt/photoIds/moments. If new MediaStore drawable pending, only original R567 `refreshPages()` gets bounded retry on same live Gallery; no forced close/reopen.
4. Existing R572 original functional settings (8 reordered actions / last fast ON / Naver favorite using original first-party writer / status toast auto-expiration) protected byte-for-byte except necessary JS/CSS and independent native provider.
