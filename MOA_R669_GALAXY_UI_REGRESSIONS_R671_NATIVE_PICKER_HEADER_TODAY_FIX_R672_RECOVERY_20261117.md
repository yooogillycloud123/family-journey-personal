## Precise source defect CONFIRMED — today/day picker empty groups
R669 active `moa-r667-vertical-calendar.js` function `r665PickerGoDay()` changes `r619AuxDate` and re-renders but failed to reset `r619PickerGroupCount`. `r619RenderPicker` rebuilds `r619PickerGroups` but `appendGroups()` begins its loop at the **old cursor**, silently skipping every media group at the new date. This explains the user seeing a blank list after TODAY even though photo IDs may exist. A second independent risk: day-only `r619PickerAssets` only uses `st.byDay` and `st.byVideoDay`, which can hydrate later than `st.photos/st.videos`. R671 resets groupCount for EVERY picker render and every day jump; TODAY always rerenders even on same date, forces scope day, and read-only combines byDay and same-local-date filtered flat lists; de-duplicates by ID; does NOT modify original IndexedDB/photo storage. Exact UI source diff restricted to picker functions, and original PHOTO/QuickRecord JS before `function r619PickerAssets` and after `async function r619CommitPicked` is byte-exact R669.
