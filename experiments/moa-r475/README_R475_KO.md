## 이번 빌드의 실제 반영 범위
1. 기존 일기를 열면 동일한 웹뷰 안에서 하나의 통합 사진 달력으로 전환 시도. 원본 수동 선택/자동 사진 데이터는 별도 복제·이관하지 않고 **한 달력에서 표시 소스**만 전환.
2. 사진 일기 날짜를 열면 27px의 작고 오른쪽 정렬된 `사진형 / 상세형` 스위치. `사진형`: 기존 R472 인라인 사진 스크롤 + 간편 입력 + 음성 선택기. `상세형`: R463 원본 일기의 제목/본문/시간대별 상세·편집 엔진을 **그대로 호출**, 상단 동일한 작은 스위치와 배경·카드·모서리 스타일만 조정.
3. 미저장 간편 일기 내용이 있으면 상세형으로 전환을 막아 먼저 저장하도록 안내. 기존 메모, moments, activities, 사진 선택, 음성첨부를 새 DB로 마이그레이션하지 않음.
4. 가족 일정은 기존 `moa-family-calendar-v1/events` 저장소에서 읽기 전용 참조. 이미 로딩된 원본 MoaFamilySchedule getter를 사용하고, 일정 DB가 존재한다는 사실을 열거할 수 있는 WebView에서만 추가 read-only 조회 수행(없는 DB를 실수로 생성하지 않음). 날짜 점/날짜 내 목록 제공, `일정 관리`는 원래 가족일정 편집기로 이동.
5. 달력 칸 간격 3px→1px, 개별 칸 모서리 제거, 날짜는 사진 안에 겹치게, 날짜 선택 강조·오늘 구분·작은 일정 마커. 하단 5탭 `일기 / 나의 지도 / + / 기록 / 설정` 유지.

## 반드시 구분할 미완료 부분
- **R463 네이티브 고급 갤러리 물리 엔진을 새 사진 영역에 완전히 이식한 버전이 아님.** R472의 WebView 가로 scroll snap 기반이며 원본 R203 OverScroller의 실제 운동학적 일치는 미검증.
- 새 화면 안 영상 `content://` 경로, 실제 1% 탐색/음량 스와이프/프레임 캡처/사진 확대/고해상도 풀뷰는 미완성·기기 검증 전. 새 화면에서 원본 영상으로 넘어갈 수 있는 fallback이 남아 있음.
- 14,000장 사진/1,000개 동영상 실제 메모리·재생·성능, 저장 트랜잭션, 가족 일정 초기 읽기, 네이버 비점유 저장, 안드로이드 실행·설치 후 상태까지 **실기기 PASS를 주장하지 않음.**
- 상세형은 **같은 날짜의 원본 편집기를 재사용**하므로 모든 상세 기록을 사진형 안의 단일 DOM으로 재구축한 것은 아님. 스타일·상단 전환만 통일한 1차 통합.
- 사용자 승인 골든 **R463 그대로 보존**. R475는 다음 실기기 검증 후보.

## 사용자 검증 순서
1. R475 덮어쓰기 설치(앱 삭제/데이터 삭제 없이). 일기 탭 진입 → 하나의 사진 달력 자동 열리는지 확인.
2. `내가 고른 사진`과 `전체 사진` 표시 범위, 달력 사진과 가족 일정 점을 확인.
3. 하루 선택 → 사진형 큰 화면 → 위쪽 27px `상세형` 전환 → 원본 시간대별 자료 → `사진형` 복귀 확인.
4. 중요하지 않은 날에서만 글 입력/저장, 가족 일정과 원본 바로기록·네이버·원본 갤러리 동작 확인.
5. 문제가 있으면 앱 데이터를 지우지 말고 R477 복구본을 덮어쓰기. R477 복구 시 R475의 추가 통합 UI만 사라지고 R463 기존 기능 복구.
