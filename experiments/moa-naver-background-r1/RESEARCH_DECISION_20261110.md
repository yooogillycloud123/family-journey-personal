# MOA 네이버지도 실계정 즐겨찾기 — 목표 불변 기술 의사결정

**목표(동일):** Galaxy MOA 화면에서 장소+메모+선택 리스트 저장을 누르면 타사 네이버 앱 전면 전환 0회, Shizuku/루트 0, 사용자 소유 네이버 계정에 신규/기존 리스트로 등록, 서버 재조회로 검증. 가족 사진/녹음/일기/원본 GPS·기존 골든 파손 0.

## 실패 실증과 원인 분류
- 사용자의 R229/R231 `↶ MOA` 한 번 터치 동일 사진 복귀는 기기에서 PASS. 계속 보존.
- R231 WebView는 네이버지도 **앱 설치/열기** 모바일 랜딩 + MOA의 앱 URL 차단. 지도 로그인이나 즐겨찾기 쓰기 성공 없음.
- R233 WebView PC UA 변경 후 `https://map.naver.com/?app=Y&appmarket=N`에서 `net::ERR_TOO_MANY_REDIRECTS`. **R233 실기기 실패**. Naver 인증 차단이라는 단정 금지. 해당 실험 APK 추가 배포 중단.
- 이전 `fj-naver-favorites.js` + Naver Accessibility 조작은 실계정 앱 저장 UI의 성공 표시를 보여줬지만 스마트폰 화면을 차지함; 엄격한 비점유 요구를 충족하지 않음.

## 외부 대안 조사
A. **서버에 공개된 네이버 공식 북마크 쓰기 API**: 확인 못 함. 일반 지도 SDK/URL Scheme 및 OAuth만으로 개인 즐겨찾기를 쓰지 못함.
B. **Chrome CDP/Playwright 실제 브라우저 UI**: 공개 구현이 리스트 생성 + 장소 저장 절차를 제공. 화면 점유가 *휴대폰이 아닌 PC*에서 발생하도록 headless를 사용 가능. 본 R1은 독립 재구현 + 최초 수동 로그인 + UI 쓰기 + 읽기 전용 재조회 + 오프라인 대기열·중복 방지. **현재 가장 실증 가능성이 높은 즉시 개발 트랙**.
C. **네이버 비공개 REST/GraphQL 호출**: 2026년에 보고된 `ncaptcha token is invalid`; 엔드포인트 가정, 토큰 위조, CAPTCHA 우회는 불안정하고 계정 보호에 위험. 조회만 보조 검증으로 사용.
D. **타사 네이버 앱을 비공개 VirtualDisplay에서 자동 조작**: Android 앱의 권한 격리상 무루트/무Shizuku로 임의 실행 보장 불가; 외부 앱의 네트워크 인증을 오프스크린에서 복제하는 통로가 아님.
E. **Android 자체 전체 브라우저 엔진(GeckoView/전용 Chromium 패키지), 항상 켜진 개인 NAS/VPS**: 향후 연구 병행. 브라우저 엔진 패키지 크기, 실제 NAVER 호환, 로그인·CAPTCHA·서비스 약관, 사용자 데이터 보관 등을 검증한 뒤에만 개발 승격.
F. **네이버 앱 Accessibility 현재 방식**: 별도 로그인 필요 없고 보존하되 화면 차지하므로 명시적 전면 모드 fallback; 목표 완료로 선언하지 않음.

## 단계별 목표
P1 PC R1 Engine: 독립 대기열, 인증 통신, 사용자 소유 브라우저, 리스트 UI/저장 UI, 목록 재조회, 실제 Chromium mock 테스트 → **구현/오프라인 테스트**.
P2 Real NAVER E2E: 사용자 소유 PC에서 한 개의 특정 무해한 장소로 리스트 자동 생성+저장+재조회 확인, UI 선택자 변경 수리, 첫 로그인 사용자 직접 진행 → **미실시**.
P3 Android MOA integration: R233 최신 서명 패키지의 원본 기능 유지, 위치정보 즐겨찾기에서 토큰·인증서 핀으로 전송, 오프라인 outbox/상태 UI, 네이버 저장 완료 표시 전에 readback 필수 → **참조 Android 소스만 구현, APK 미생성**.
P4 Phone-uninterrupted 10건: 실제 화면 전환 없이 사진/일기/녹음을 유지하며 10회 성공, 오류 복구, 자동 신규 리스트 10/10. → **미실시**.
P5 Android-only/no-PC research: 자체 브라우저 엔진 vs 공개 지원 API, 별도 등록없이 실행 가능한 방법 계속 조사; PC가 전제되는 형태를 최종 사용자 요구를 모두 충족한 것처럼 포장하지 않음.

## 완전성 규칙
실제 계정에서 목록 재조회 못하면 상태는 `SUBMITTED_UNVERIFIED`; 단순 클릭/HTTP 200을 VERIFIED로 승격 금지. UI 변경 시 스크린샷/DOM 민감정보 공개 GitHub에 업로드 금지. 개인 세션·사진·GPS·주소·신분정보 비공개. 기존 R227 골든 및 실제 기기 확인 R229/R231 경로 회귀 금지.
