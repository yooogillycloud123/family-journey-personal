## 2. Specific changes and technical root causes
1. **Full Gallery selection handoff**: `MoaR507InlineGalleryProvider.tick()` previously returned early whenever `fullNativeOpen`, never syncing the original native Gallery `index`/current MediaStore ID. R539 caches selected index & ID while original Gallery is open and sends `__moaR539AdvancedSelection(index,id)` **before** `__moaR531AdvancedClosed()`. JS uses ID first, safe index fallback, adjusts same daily `ui.idx` and fallback WebView track; re-enters in-card native renderer at CURRENT selected image. Do not overwrite last sampled index after `Gallery.close()`, which might reset it.
2. **Grey/blank app return**: R535 required `ownsGallery`, same object `galleryRef` and `__moaR507NativePending` to all survive the app's Activity pause/resume; any one could be lost while SurfaceTexture is discarded. R539's guarded rebind verifies **trusted https://familyjourney.local WebView, active SAME photo diary day, session token >0, not original fullscreen**, then clears/rebuilds only in-card host; it can handle lost owner/instance, closes native old Gallery without invoking usual Back/day exit, `__moaR539RecoverAfterReturn` preserves selected index and data and starts a new token. Adds JS visibility + validated WebMessagePort wake for cases without normal lifecycle callback. Real Galaxy state still needs testing.
3. **Micro-jitter**: Separate WebView and Android sibling compositor surfaces cannot be perfectly frame-locked by 120Hz one-way geometry alone. R539 default ON optional **single-compositor scroll proxy** shows underlying WebView photo/video poster while keeping native Gallery touch owner/player, makes native sibling alpha=0 only during active vertical scroll, then sends final exact geometry and `s0` message. Android applies alpha=1 and calls back `__moaR539NativeScrollSettled`; WebView proxy closes only after acknowledgement (bounded 320ms fallback). Native positions use fractional GPU translation instead of rounding 1px oscillations. User can toggle [스크롤 중 화면 고정] in photo ⋯ options. During a video scroll, the preview may appear as a still image; this is an intentional rendering tradeoff, NOT a new video decoder.

In detailed screen keep original actual `.moa-r191-day-menu-trigger` (handler/data) but visually hide its *old* header, day stats/intro headings/shortcuts; native original detail timeline, diary storage, recording and settings functions remain source-of-truth and accessible by new ⋯.
