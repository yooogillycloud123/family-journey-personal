# MOA permanent settings UI contract — user requirement 2026-11-28
This is a mandatory future Settings release gate, not a promotion or alteration of user Golden R771/R759. Applies to adding, moving or changing ANY Settings item. Existing functionality, preferences, package, storage, bridge, callbacks and user data remain protected.
- Version row must be first, with actual PackageManager version; existing in-app GitHub update action immediately below it. Never use a hard-coded fake version. Update remains an action, not a pretend accordion.
- Use the established device-sync/photo-and-data visual language: consistent rounded bordered cards, uniform margins/padding/header typography, clear card-vs-page contrast, support all existing themes. Bold title only in collapsed headers; do not show redundant subtitles, helper prose, legal/diagnostic details in the collapsed list.
- All expandable panels, including calendar navigation, auto-learning, quick-record, Naver return button, photo/data, home shortcut, design/theme, fast scroll, help, map/extensions and future items, use right chevron closed, down chevron open, same location and stroke, default collapsed. Direct actions retain original handlers and are not fake expandable controls.
- Place descriptions, attribution (do not delete legally required credits), diagnostics and explanatory text inside the correct expanded card; maintain actual visible error feedback when needed.
- Preserve original nodes/event listeners/IDs, settings values, existing hidden policy, actions, permissions, data and native APIs. Never clone/replace controls just to restyle. Scope CSS to Settings and ensure selectors do not affect gallery, learning cards, maps or diary.
- Automatic study state is not inferred from Android job reservation: read actual canonical registered media and stored validated cards; display full/partial/missing, retry/held, actual last saved time, recent worker signal and current phase. Never label a merely scheduled job as generating. Missing or stale signals and read errors must be explicit; don't claim physical background success from a host mock.
- Mandatory pre-release review: compact screen, tablet, light/dark, all cards closed then open, no clipping or wrap collisions, correct arrow direction, version/update order, existing actions and prefs, actual learning counts and state, physical device smoke test. Keep unsigned candidate, signed beta, real physical PASS and user Golden approval distinct.
- R771 is immutable user Golden until user explicitly approves a new Golden; R787 is a beta only. This file is the permanent rule, not a modification to Golden branch or APK.
