## Actual engineering changes
1. New idempotent `MoaGallerySmooth` helper is embedded in both existing loaded viewer JS files (no extra HTML loader or new APK members). **One shared index/fractional scroll position** controls main stage preview slides *and* a filmstrip. Previously filmstrip input and main image were independent.
2. Filmstrip now uses an **absolute-positioned virtual track** anchored to the center: thumb step **55 CSS px**, current thumb stays aligned to viewport center, user scroll updates position continuously; only ~20–40 nearby thumbnail DOM nodes instead of reconstructing 13 buttons each selected item. Capped caches/pending requests; full 700-media catalog does **not** become 700 DOM buttons.
3. On every scroll/drag frame, **prev/current/next visual preview slides** use `translate3d` driven by the fractional track position; on release a ~205ms decelerating animation chooses the nearest item, then only **one** final full-media render commit (so M4A/photo/video media isn't reopened on every pixel).
4. Native same-Activity Android `VideoView` now uses `MotionEvent.ACTION_MOVE` to translate the actual video layer along with finger and reports `drag:<fraction>` events to WebView timeline; the filmstrip responds to this movement. Conversely thumbnail dragging calls new read-only-gesture `MoaLocalAudio.shiftInlineVideo(float)`, shifting/fading current native video overlay to reveal adjacent frames. Swipe commit navigates next/previous without separate native player Activity.
5. Both day Diary viewer and monthly report viewer use the same real-time rail/visual gesture model; old full-resolution photo loader, cached previews, video auto-muted play/seek/capture, original native fallback, GPS/location, timeline/700-grid, media share and back navigation remain intact.
