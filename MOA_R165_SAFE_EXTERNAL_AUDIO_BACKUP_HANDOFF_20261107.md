## User request / technical tradeoff
User wants M4A recordings to survive uninstall like Gallery media, with no regression to existing live dictation, capture recording, media player, automatic transcript, diary/memo linkage, photos/video/Maps/Family Calendar. Zero risk cannot honestly be guaranteed without physical QA. We therefore retain all R163 original audio paths and make only separately consented, SHA256-verified external copies. Storage **increases** when backups are enabled, until a later verified external-primary/reconnect phase. Do not infer speed or capacity improvement from this interim build.

## Feature details and limits
1. In capture “바로 기록”, scrollable body has new **기존 음성 전체 외부 안전 보관** button and OFF-by-default **새 녹음 자동 외부 복사** checkbox. User confirmation explicitly warns other media apps can see these M4A recordings and app-internal originals still exist (more total device space). The existing fixed keyboard footer, text-only microphone, M4A recording, playback/pause timer and Diary save buttons remain unchanged.
2. Full backup scans only `getFilesDir()/moa-original-audio/YYYY-MM-DD/*.m4a`; each public copy goes to **`Music/MOA-Recordings/YYYY-MM-DD`** via Android MediaStore Audio (API >=29, no broad storage permission). Source original is never moved, modified or deleted.
3. New MediaStore row first marked `IS_PENDING=1`; writes in streaming 64KiB buffers, reopens URI, verifies exact byte count and **SHA-256**, then publishes `IS_PENDING=0`. New incomplete row is deleted only on failure; existing external recordings are never deleted. App-private SharedPreferences stores verified URI/hash; retries check original and existing copies. A backup may be interrupted if Android terminates the process; retry is safe.
4. Optional new-recorder mirror is asynchronous only AFTER R163 M4A saved; never blocks/interferes with existing SpeechRecognizer or MediaRecorder. Uses same internal voice original and metadata as R163.
5. This is **RAW AUDIO backup only**, **NOT** full Diary/text/photo-link backup or automated restore/relink after app uninstall. Those require future design and physical validation, ideally an encrypted/opt-in portable metadata manifest and Storage Access Framework import. Without those, preserved outside M4A could be manually retrieved but Diary's internal metadata would still be lost on uninstall. Never tell user it is a full backup or a zero-capacity-overhead migration.
