### Root of broken return (confirmed in binary)
`MoaMomentAudioHostActivity.onPause()` **unconditionally** called `MoaNativeGallery.close()` when launching an external app, including NAVER Maps. Thus when NAVER relinquished foreground, MOA's native gallery had already been destroyed and underneath Diary calendar displayed. R227 guards this close *only while native Gallery itself has initiated an external NAVER Maps visit*, then `onResume()` clears the flag and restores the exact in-memory media IDs, index, playback position, and rail; video restarts only if it was playing before the link. Other onPause cleanup (M4A player/recording, speech, old video overlay) and onDestroy remain identical. If process is killed by Android while backgrounded, this in-memory guarantee does not hold; device/low-memory test pending.

## User-visible design decisions

1. **Remove redundant top chrome:** top Back/count/ellipsis text and tappable widgets are hidden in both chrome-visible states. The original Android system Back gesture/button remains, and a LONG PRESS of the metadata card retains legacy "원본 갤러리 열기 / 공유 / 모아 기존 상세·GPS 보기" actions without a visible 48dp toolbar.
2. **Fully-readable capture details:** photo/video capture time remains fixed at top. Address changed from one-line `END` ellipsis with fixed 88dp text button to dynamic WRAP_CONTENT up to six lines and a touch-accessible 44dp native vector **map-pin icon** at right. Card fits content and overlays the video/photo; it never changes the full-size stage/72dp lower rail geometry.
3. **Precise GPS source order:** existing exact-ID on-device diary/map index → original unredacted MediaStore EXIF `MediaStore.setRequireOriginal(u)` when `ACCESS_MEDIA_LOCATION` granted → other standard EXIF/MediaStore/video metadata as feasible → honest absent-GPS/permission message. No coordinate inference from neighbors or fabricating GPS; old map index is sampled to max 30k rows. `Geocoder` reverse address lookup remains background-only and stale results ignored.
4. **Naver app:** official `nmap://place?lat=...&lng=...&name=...&appname=com.juhyeon.familyjournea` exact-coordinate link replaces HTTPS search stacks when Naver installed; app launch uses `CATEGORY_BROWSABLE` and `com.nhn.android.nmap`. If app not installed, existing HTTPS search fallback. **IMPORTANT: Android/Naver controls Naver's own internal Back stack; a strict one-system-Back guarantee cannot be proven or imposed by MOA.** Official direct-place deep link is intended to reduce intermediate screens. MOA gallery still stays open and reappears on foreground, rather than Diary calendar. Official NAVER URL Scheme: `https://guide-gov.ncloud-docs.com/docs/ko/naveropenapiv3-maps-url-scheme-url-scheme`.
5. **Selected video strip expands to right:** R225 only enlarged the selected clip ±86dp and drew frames inside that tiny container. R227 animates selected rectangle from current thumbnail to near the full **available lower filmstrip width**, starting near left margin, pushing thumbnails left/right, preserving selection and full-size stage. The expanded strip accepts horizontal drags **anywhere across the rail** for seeking; tapping ANY part of expanded filmstrip collapses. Non-expanded rail still retains R203 true inertia and moves the upper full image with its fractional index; full-size stage remains one-photo-per-swipe; video play/capture/mute controls and placement retained.
